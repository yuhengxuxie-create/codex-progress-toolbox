# v1.6.0 更新说明

**v1.6.0 · 2026-09-12** 以下变化对比 [上一公开版 v1.5.0](https://github.com/yuhengxuxie-create/codex-progress-toolbox/releases/tag/v1.5.0)。安装包和升级包见本版本 GitHub Release。

本版本整理截至2026年9月12日的通用成果，包含9月10日审批和网页引用修复，以及9月11日文件路径校验与安全恢复。完整安装和旧版升级入口见下文。

## 最值得关注的变化

1. **飞书操作更直观。** 新增功能中心、会话查询卡片和指令入口；按钮可以直接点，文字入口统一为 `.功能中心`、`.新建个人会话` 等写法。
2. **找任务、接着聊更方便。** 飞书和百宝箱都能按名称、描述或时间线索模糊搜索；也能回复自己之前已关联任务的消息继续交流。
3. **成果文件自动发到飞书。** 除了原有图片回传，本轮明确交付的文档、表格、压缩包、脚本等本机文件也会自动发送；回复文件即可继续原任务。
4. **该收到的答案更少漏掉。** 直接问题的答案、可审阅成果、重要变化和需要处理的事项会通知；内部过程保持安静，图片和文件不再依赖文字总结是否发送。
5. **业务停止后仍可远程救援。** 新增独立通信守护和 Windows 恢复监督；守护在线时，在飞书发送 `.启动飞书机器人` 即可请求恢复业务。
6. **增加额度重置消息预警。** 飞书可查看预警状态和最近记录，百宝箱可查看提醒及已读状态；不会替你使用重置卡。
7. **百宝箱更清晰、窗口操作更可靠。** 更新主题、图标和文字显示，改进搜索、表格列宽及抽屉布局，修复最小化、最大化与缩放问题。
8. **整套生态升级更方便。** v1.5.0 用户使用专用快捷升级入口；升级后可从百宝箱检查后续正式更新，程序和用户数据一起按受控流程处理。

## 飞书任务管理

- 功能中心集中提供创建、查询、搜索、监测、额度与使用说明。会话查询支持卡片选择和翻页，手机上更容易辨认任务名称。
- 新建个人会话或项目内会话时，按提示选好项目和运行方式，回复新建提示并直接写任务要求即可，旧模板仍可使用。
- 模糊搜索可只填部分线索；找不到时可按提示扩大范围。深度搜索会使用 Codex 额度，扩大范围前会说明预计成本。
- 在已有概览、完成通知、任务图片或文件上回复即可续聊；自己之前已经可靠关联任务的消息也可以继续引用。同一条有效消息支持多轮回复，回执区分“已排队”和“已追加”。
- 增加完整原文回看与归档入口。查看原文不会把后续通知改成全文；按钮归档先核对确认，结果未知时不重复提交。
- 直接文字入口使用行首英文半角 `.`，例如 `.查询会话`、`.查看指令列表`。旧无点精确入口会提示新写法；按钮、引用编号、任务正文和既有 `/project`、`/commands`、原生 `/`、`$` 语法保持原操作方式。

## 通知、图片与文件

- 通知按当前请求判断：独立问题的答案不会因为整个长期项目尚未结束就被省略；重复事实没有变化时不反复通知，失败和未完成项会如实说明。
- 本轮新生成的图片独立发送，文档、表格、幻灯片、压缩包、音视频、代码等明确交付的本机成果文件也可自动发送，保留文件名和任务关联。
- 成功保存交付副本后，修改原文件不会改变该副本；保存前原文件变化或消失仍可能导致失败。单件失败不拖住其他文件；结果不确定时暂停该件，避免重复发送。首次启用不会批量补发历史文件。
- 普通文件须非空且不超过 30MB。远程链接不能直接当成本机附件，无法验证、文件缺失或平台拒绝时会说明原因。代码行号引用和普通网页来源不视为附件。
- 新增额度重置消息预警及双端记录。预警是对公开消息的核验，不代表你的个人账户已重置；来源不可用时会提示覆盖不完整。
- X 来源限流后按接口分别等待，重启后保留等待进度，其他来源继续检查。百宝箱显示直接发现的实际重试计划，并区分备用来源本次可用、失败或仅沿用缓存；这不代表已经解除 X 限制或补全全部消息。

## 守护与百宝箱

- 通信守护与任务业务分开运行。普通“停止”保留救援通道，百宝箱刷新或重新打开不会擅自取消停止选择；完整退出会关闭救援。
- Windows 监督检查守护崩溃和心跳异常，有限重试并在连续失败后暂停。只有通信在线、守护健康且业务就绪，才认为启动成功。
- 远程救援需要电脑开机、网络可用、原 Windows 用户仍登录且守护正常；不能给关机的电脑远程开机，注销或断电时也不能保证通知。
- 百宝箱新增共享模糊搜索、预警记录和生态更新入口；改善主题、原生文字、可拖动列宽和任务列表布局。最小化进入任务栏，关闭窗口收至托盘，完全退出仍通过托盘菜单操作。

## 修复与可靠性改进

- 首次安装或v1.2迁移在运行时建立之前失败时，按事务证据恢复原目录，不再因新目录还没有Python而阻塞回滚；已有守护状态或无法确认的运行情况仍会拒绝覆盖。
- 旧完整生态升级中运行时安装失败时，也可在已核停服、恢复任务禁用且配置与状态未发生新变化的前提下自动恢复；缺少这些证据时保留备份并明确报告，不能声称已经恢复。
- 结构化文件标记正确分离路径与说明属性，兼容 Windows `/C:/` 路径；所有现支持的文件发现、保存和发送入口统一进行准确路径及文件身份校验，不猜测相似文件名。
- 同一进程内，本轮同一路径的文件由不可用变为可用时，只有尚未提交的本地失败可以安全恢复；已发送、提交中和结果未知的记录保持原状态，重启不会补发历史拒绝。外部网络与平台错误仍可能发生。
- 普通网页引用不再因网址中的“下载”等字样而误报文件发送失败；明确交付的附件仍会校验。
- 补充等待批准时的独立飞书提醒，发送前复核当前状态。无法远程批准时，提醒回到 Codex 原任务审批框操作，回复 A 不会代为批准。
- 减少审批观察的重复扫描；监测列表缓存15秒，新加或移除监测可能多等待最多15秒刷新，之后还需轮询和状态读取时间。
- 修复飞书连接线程已停止却仍显示“正在重连”的问题；区分仍在重试与连接已失败，失败时提示在本机检查并重启通信，不再误称正在自动恢复。
- 收紧额度预警判断，减少把推测、疑问、玩笑或过去动作当作新预警；补充官方故障补偿意向和低预测与明确官方承诺冲突的提示。夜间不发起新的预警投递，已提交的请求仍记录实际结果；已发放重置券的通知保留。
- 修复同一轮先给出实质答案、随后内部收尾时，早先答案被遗漏的问题；通知判断结合本轮真实提问、各段正式答复及后续更正。
- 修复后台维护命令偶发弹出黑色控制台窗口的问题。
- 减少任务目录的重复处理，降低任务较多时的轮询开销；实际读取任务记录时仍保留归属校验。
- 修复部分任务标题被首轮提示词替代、任务历史更新较晚时漏掉新结果，以及历史消息回复关联和排队恢复问题。
- 修复新生成图片因文字静默而漏发、历史晚到图片误补发，以及真实媒体上传参数不兼容的问题。
- 成功投递后的回顾消息不再被误报为缺少附件；真正的新交付缺少文件路径时仍会提示。
- 业务恢复并经过核验后，清除当前超时错误提示并保留历史记录；增加慢轮询诊断，方便排查延迟。
- 修复百宝箱文字重影、遮挡或裁切、部分窗口缩放累积、标题按钮重复触发，以及最小化和最大化行为异常。
- 加强升级前检查、停服备份和失败回滚；保留历史关联、待处理状态、自定义插件及恢复设置，拒绝不能安全迁移的数据路径。
- 升级失败时不再未经核实显示已自动恢复，也不自动启动程序；保留材料并提示查看更新日志，核对恢复结果后再处理。

## v1.5.0 用户升级前请看

1. **下载 `upgrade-from-v1.x` 包**，解压到旧安装目录之外并核对校验值。退出百宝箱后运行 `快捷升级.cmd`。旧版没有新版内置更新入口，不要只换 EXE 或用模板覆盖原配置。
2. **保留原飞书应用和绑定，不必重新配对。** 本次没有增加权限 scope，但需要核对原有四项权限，并为卡片按钮添加长连接回调 `card.action.trigger`。
3. **底部菜单按需配置。** 使用功能中心菜单时，添加 `application.bot.menu_v6` 事件和菜单事件键 `progress_wx_feature_center`；未配置菜单也可发送 `.功能中心`。按开放平台要求保存、发布自己的应用配置并完成审核。
4. **保留备份，使用同一 Windows 用户升级。** 升级处理程序、配置、状态及插件；失败时恢复同一份备份。跨电脑或跨账号迁移凭据需要另行处理，回滚不会自动合并升级后的新数据。

完整步骤见 [升级与回滚](../UPGRADE.md)、[飞书配置增量](FEISHU_UPGRADE_PERMISSIONS.md) 和 [新版文字指南](USAGE.md)。新用户使用 full 包；GitHub 自动生成的 Source code ZIP 不能代替含运行载荷的安装包。
