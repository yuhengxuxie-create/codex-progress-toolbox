# 变更日志

## 1.6.0 · 2026-09-12

### 文件交付统一校验与安全恢复

- 支持结构化输出文件标记和 Windows `/盘符:/` 链接，遮蔽后续操作按钮中的路径，区分准确文件路径与地址编码；存在编码歧义时停止猜测。
- 各现有文件入口在队列及快照读取时共用普通文件、完整父路径、大小和身份校验；生成图片保留原有格式及摘要检查。
- 当前进程内同一轮同一准确路径重新有效时，仅未提交的本地失败可恢复，保留失败历史和已发通知；已成功、已提交和未知结果不自动重发，重启不回补历史拒绝项。
- 发送失败提示区分路径未找到、无读取权限、文件变化及平台未知结果；通过原子状态核验避免文件恢复后仍发旧失败通知。没有新增飞书权限或第二套平台重试机制。
- 任意错误文件名仍须原任务返回实际生成路径，不按相似度、扩展名或修改时间搜索文件。升级边界见 `docs/BACKEND_DELIVERY_UPGRADE.md`。

### 2026-09-10 审批提醒与网页引用修复

- R2将监测注册表缓存15秒，仅真实pending或此前pending需核解除时读取完整local turn，保留每次远端轮次身份核验；新订阅/移除可延后至缓存刷新，另计轮换及IPC开销，不增加伪心跳或放宽超时。
- 区分网页引用与附件交付意图，URL自身的路径或查询词不再触发交付判断；明确文件交付仍执行原校验。
- 独立读取Desktop结构化待审批状态，发前复核、持久等待身份及guardian异步去重；有效Hook优先，没有远程审批句柄时仅提醒返回原审批框，不接受回复A执行审批。
- 既有业务表不迁移，新增独立审批观察状态文件。历史失败、未知投递不清零、不补发。本节修复纳入 v1.6.0 正式版本。

### 可靠性修订

- connection_snapshot增加thread_alive，guardian精确记录failed及固定安全原因码，连接已停止时提示本机检查重启；存活重试仍为reconnecting，恢复清本次错误，离线转failed不新增重复通知。不改SDK清理/代理/自动重启策略。
- X直接发现、正文与父关系核验独立持久429退避，仅保存白名单解析限流字段，按收到响应时刻计算等待；缓存/跳过不刷新真实请求成功时间，旧cursor兼容且schema不变。
- 收紧未来额度承诺、B1独立官方信号及过去时间判断，补X故障补偿B3和低概率冲突；夜间出站不领取/提交，后续已授权的announced_available保留。CLI增加可选端点/备用/本次核验字段，规则及边界见docs/X_RESET_ALERT_RULES.md。
- 修复同轮多段final早先答案丢失：以精确历史指针为锚保留有序材料，真实用户请求优先精确历史项，飞书追加需同轮来源与本地成功投递交叉验证；截断扫描不再误用插件列表。CLI/API分段保留输入空间和更正，取消内部继续工作必静默的旧绝对规则；旧静默及未知投递不重置、不自动补发，schema不变。
- whoami/icacls 后台权限辅助命令显式使用隐藏控制台；目录选择跳过未读取 rollout 的归属路径计算，实际 snapshot/turn 读取仍执行安全归属检查，无新增缓存。
- 业务经核验恢复后清除当前超时错误并保留历史，慢轮询仅记录有限阶段耗时；既有未知结果不清零。
- 修复成功投递回顾文字被误判为缺少附件路径，保留真正新交付的缺路径提示与显式文件识别。

### 机器人文字入口点前缀

- 直接自然语言入口及别名使用行首半角 `.`，旧无点精确入口提示新写法，未知点命令不转成正文；按钮、引用编号和新建正文不变，`/project`、`/commands` 及原生 `/`、`$` 语法兼容。
- 机器人入口不消费暂存图片，精确 `.发送`、`.取消` 仍处理暂存；文字说明同步，schema23 不变。

### 成果文件与新建对话

- 修复真实 SDK 媒体上传的 keyword-only `kind` 调用，补充适配器到真实 SDK/HTTP 边界的文件与图片回归；拒绝结果增加安全异常类型诊断。R2 的旧 mock 接受错误位置参数，曾漏检真实上传前失败。

- 本轮明确交付的本机文件保存独立快照并逐件持久投递，原生生成图独立发送；文字静默不丢附件，首次启用不回填历史，未知结果不盲重发，文件回复关联原任务。
- 业务库升级至 schema23，新增文件投递状态、媒体类型和失败通知身份；通信库保存上传 key 后再发送消息，重启保留未知结果及快照引用。
- 个人与项目新建提示支持引用回复首轮正文；项目及运行方式先明确选择，保留旧模板入口。

### 改进

- 全局修复首轮提示词冒充会话名称：标题与 preview 的等值、截断和高相似薄包装包含关系统一判为提示词派生，不再让 `/goal` 或其它包装绕过来源判定；人工名、Codex 自动标题和可靠 session_index 标题按同一优先级解析。
- `list-threads`、`monitor-list`、飞书项目/个人目录、搜索详情和进度通知统一使用共享展示名解析器；列表不再输出内部 subagent。JSON schema 仍为 v1，新增向后兼容的可选 `title_origin`，百宝箱无需复制标题规则。
- 状态库升级为 schema 14，新增按 thread_id+内容哈希持久的历史异常恢复名；列表刷新零模型消耗，正常搜索可顺带复用同轮结果，显式 `repair-thread-titles` 维护命令每次最多 3 个 Luna 批次且不回写 Codex 标题。真实人工/自动标题一出现即覆盖恢复名。
- 会话搜索旧内容哈希的描述、证据和判断缓存不再随新版本写入而立即物理删除；精确哈希保证旧判断不会误命中，旧版本仅由既有 90 天清理窗口回收，保留审计与回滚时间。
- `session-search` 新增 `--cache-mode ephemeral` 隔离验收模式：只读在线复制生产状态后在临时 SQLite 中完成真实搜索，退出即清理且不回写；默认 `persistent` 仍服务真实用户缓存。每个 progress 快照明确显示当前缓存模式。
- 记录 2026-08-29 首次流程失败：百宝箱两次 UI 验收误用默认持久模式，标题来源进入内容哈希后刷新约 69 条证据缓存，并使 79 条旧哈希判断按旧逻辑删除；这些判断与新哈希不兼容、无运行前备份且不应伪恢复或用 Luna 重建，消息、监测、会话和其他生产状态未丢失。
- 普通进度汇报与会话概览支持在有效期内持续多轮引用：父消息稳定定位会话，每条飞书入站消息使用独立持久子投递，连续多轮与两条快速回复均严格保序且各自恰好投递一次；RPC、审批、人工输入和 hook 仍保持一次性。
- 飞书回复回执区分“已排队”与“已追加”；父消息过期、归档或线程不可访问时给出准确提示，Desktop 暂不可用和服务重启不会消耗父消息或丢失安全待投递回复。
- 修复 Codex Desktop 工具管道发现：Windows 下优先枚举当前仍存活的命名管道并用 `tools/list` 验明身份，日志候选仅作兼容回退，避免长期运行后只命中陈旧日志管道。
- 修复飞书引用回复的故障隔离：Desktop 在正文认领前暂不可用时，持久 ReplyJob 采用有界等待重试，飞书通道、进度监测和管理命令不再被全局停止。
- 保持 exactly-once 安全边界：Desktop 明确拒绝或能证明写入前失败时释放 claim 并安全重试；写入后结果未知仍保留 uncertain 并触发安全停机，禁止盲目重复提交。
- 图文合并、原图路径与普通文字统一使用同一持久投递状态机；排队回执只说明已安全入队，不冒充已经送达 Codex。
- Windows 进程身份校验会读取进程退出码；即使旧内核对象仍可查询，也不会再把已退出的旧 PID 误报为运行中的服务。
- 会话搜索候选页改为每个候选独立分段，明确展示匹配度和匹配说明。
- 搜索唯一命中、选择候选后的详情与“查询个人会话 → 选定 p01”共用同一消息分块规则。
- 补齐搜索字段的飞书富文本标签，只有字段名加粗；正文、链接和命令文字保持普通字重，并稳定保留段落空行。
- 搜索候选统一以 `序号｜《会话名称》` 显示，唯一命中与选择详情中的名称也只包裹一层中文书名号；标题正文保持普通字重。
- 修正 Codex 标题生命周期优先级：人工重命名最高，SQLite 当前自动标题其次，追加式 session_index 仅在 SQLite 仍为首轮提示词回退时补位，陈旧索引不再覆盖新标题。
- 只有 SQLite、session_index 与 Desktop 当前都没有可用独立标题的异常记录才使用同批 Luna 内容概括，并以 `title_origin=recovered_summary` 明确标识；飞书紧邻名称说明它不是原始标题，不新增专门模型调用，也不回写 Codex。用户人工重命名或 Codex 后续补齐标题后，权威标题会立即覆盖该概括。
- 标题来源进入搜索内容哈希；异步自动标题或人工重命名落盘后，旧恢复性缓存自然失效，当前真实名称实时优先。
- 旧版持久搜索列表增加安全降级：当前元数据不可核实时要求重新搜索，不再回显历史首轮提示词；三项线索全空时仅为缺少独立标题的最近候选执行同批命名并缓存。
