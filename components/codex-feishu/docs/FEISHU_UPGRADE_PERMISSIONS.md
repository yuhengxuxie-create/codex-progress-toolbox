# 从 v1.5.0 升级：飞书配置与数据保留

本说明对应下一版的本地候选功能，不表示新版已经公开发布。已有 v1.5.0 用户继续使用自己的飞书应用和原有绑定，不需要重新创建机器人。

## 权限有什么变化

v1.5.0 已经要求以下四项权限。本次实现没有增加权限 scope；请检查原应用是否四项齐全。

| 权限标识 | 当前用途 |
|---|---|
| `im:message:send_as_bot` | 发送文字、交互卡片、图片、原文及任务成果文件消息 |
| `im:message.p2p_msg:readonly` | 接收唯一绑定用户的一对一消息 |
| `im:message:readonly` | 读取消息及消息图片资源，核实精确引用的父消息 |
| `im:resource` | 上传回传图片、原文及任务成果文件 |

卡片采用消息接口直接发送完整 JSON，没有使用 CardKit 卡片实体创建或流式更新接口，因此不要仅因卡片使用 2.0 格式就额外申请 `cardkit:card:write`。不需要通讯录、群管理或群消息权限。

## 升级用户需要补什么

| 配置位置 | 标识或填写值 | 是否需要 |
|---|---|---|
| 事件与回调 → 事件配置 | `im.message.receive_v1` | 保留，v1.5.0 已要求 |
| 事件与回调 → 回调配置 | `card.action.trigger` | 新增；点击卡片按钮及提交表单需要 |
| 事件与回调 → 事件配置 | `application.bot.menu_v6` | 使用机器人底部固定菜单时新增 |
| 机器人 → 自定义菜单 → 事件类型菜单项 | 名称“功能中心”，事件键 `progress_wx_feature_center` | 推荐的底部入口 |
| 同上 | 名称“查询会话”，事件键 `progress_wx_session_query` | 可选；保留既有配置即可 |

固定菜单事件标识和菜单项事件键是两件事，不能互相替代。不要选择旧版 `card.action.trigger_v1`。未配置底部菜单时，可直接发送“.功能中心”或“.查询会话”；卡片按钮仍需配置卡片回调。

## 普通用户操作步骤

1. 等待新版正式发布后，下载官方升级包，先按包内说明校验文件，再使用专用升级入口。不要把模板配置覆盖到旧安装目录，不要重新配对已有机器人。
2. 打开[飞书开放平台开发者后台](https://open.feishu.cn/app)，进入原有企业自建应用，在“权限管理”中核对上表四项权限。
3. 在“事件与回调”的“事件配置”中保留 `im.message.receive_v1`。需要底部菜单时添加 `application.bot.menu_v6`，订阅方式选择“使用长连接接收事件”。
4. 切换到“回调配置”，选择“使用长连接接收回调”，添加 `card.action.trigger`。若后台要求检测到连接后才能保存，先按升级向导让已配置的后台建立长连接，再回来保存；不要填写公网回调 URL。
5. 在机器人自定义菜单里添加事件类型的“功能中心”，准确填写 `progress_wx_feature_center`。菜单名称可读，事件键必须与上表一致。
6. 按开放平台当前页面要求保存配置，在版本管理中创建并发布应用版本、完成企业审核及可用范围配置。这里发布的是你自己的飞书应用配置，与本项目 GitHub 软件发布是两件事。
7. 回到飞书与原机器人私聊，重新打开“功能中心”，依次检查底部菜单、卡片按钮和查询翻页；再按自己需要测试文字及图片回复。不要用已经发送的旧卡片判断新版排版。

如果文字收发正常但按钮没有响应，先检查“回调配置”；如果仅底部菜单没有响应，检查菜单事件订阅及事件键。平台菜单名称可能调整，以准确的英文标识为准。

## 升级必须保留的数据

专用升级器必须备份并保留原 `config.yaml`、`.secrets`、完整 `.state`、数据库及相关 WAL、已绑定用户身份、HMAC 密钥、监测列表、历史消息关联和投递去重状态，以及百宝箱配置、自定义插件和 Codex notify/hooks 的恢复记录。不能用新安装模板、空数据库或重新生成的密钥覆盖它们。

v1.5.0 后端数据库为 schema 10，本候选为 schema 23。旧数据库需要由受控升级流程迁移；`status`、`validate` 等只读命令不会替用户迁移旧库。单独换回旧程序不能降级读取新库，回滚必须恢复同一次升级前的程序和数据库备份。已有已投递与结果不确定的回复状态必须保留，不能通过清空历史来“修复”。

DPAPI 凭据依赖原 Windows 用户及系统保护上下文，换电脑或换 Windows 账号不能保证直接解密。迁移到另一台机器需要另行按首次设置流程处理，不应把旧凭据打进公共升级包。

参考：[卡片回传交互](https://open.feishu.cn/document/uAjLw4CM/ukzMukzMukzM/feishu-cards/card-callback-communication)、[发送消息接口](https://open.feishu.cn/document/server-docs/im-v1/message/create)。
